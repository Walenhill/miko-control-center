# Архитектура

## Точка сборки

`src/control-center.qml` создаёт окно, общие службы, контроллеры, страницы и IPC.
Это место связывания зависимостей, а не разметки отдельных вкладок.

## Визуальные примитивы

Повторно используемые компоненты начинаются с `Miko`:

- `MikoStyle` хранит цвета, радиусы, интервалы и motion;
- `MikoSurface` и `MikoButton` задают интерактивные поверхности;
- `MikoListGroup` и `MikoListRow` задают списки;
- `MikoToggleRow` и `MikoStepperRow` задают стандартные настройки;
- `MikoPageFlickable` отвечает за прокрутку и клавиатуру.

Страница должна сначала расширить существующий примитив и только потом создавать
новый визуальный вариант.

## Контроллеры

Компоненты получают общий `MikoStyle`; запасной стиль — singleton
`DefaultStyle`, без отдельного объекта на каждую карточку. Бесконечные анимации
работают только в видимом интерфейсе, при активной операции и разрешённом движении.

Скрытие подвкладки само по себе не останавливает её таймеры. Опрос процессов
и микрофона привязан к видимым секциям; диагностика системы запускается по требованию.

Для каждой большой области существует контроллер:

- оформление;
- приложения;
- звук;
- устройства;
- экраны;
- сеть;
- службы;
- система.

Контроллер владеет процессами, разбирает вывод, хранит состояние и выполняет
команды. В нём нет размеров карточек и визуальной композиции.

Потенциально disruptive-операции используют два шага: подготовка описания и
подтверждения, затем выполнение после явного согласия.

## Страницы и секции

Файлы `*Page.qml` собирают небольшие секции. Страница явно получает контроллер,
модели и стиль через `required property`. Переходы сообщаются сигналами вроде
`navigateRequested`.

Страница не должна неявно искать главное окно через область видимости QML.

## Реестр и маршруты

Проверки: `scripts/check.sh` проверяет синтаксис Qt 6, переводы и обработку
ошибок backend. `scripts/smoke.sh` в Wayland-сессии загружает все исходные страницы
на RU и EN с временным состоянием центра и установленными импортами ii.
Основная оболочка при этом не перезапускается.

`tools/check-updates.sh` возвращает отдельные статусы репозиториев и AUR.
`tools/snapshots.py` проверяет JSON без извлечения путей из архива, сохраняет
резервный снимок перед восстановлением и откатывает записи при ошибке.
Замена двух файлов не атомарна при потере питания; резервный снимок остаётся
для восстановления. Нужны Python 3 и jq.

`PageRegistry.qml` хранит верхнеуровневые страницы и поисковые пункты.
`Router.qml` хранит текущую страницу и вложенные разделы.

Новые маршруты используют строковые ID. Числа сохранены только для старого IPC.

## Окружение и возможности

`Environment.qml` вычисляет XDG-пути и команды интеграции.
`Capabilities.qml` один раз проверяет доступные программы либо обновляется
явно.

Отсутствующая необязательная программа должна давать объяснённое disabled-
состояние, а не кнопку, завершающуюся ошибкой.

## Сквозные службы интерфейса

- `ControlCenterState` хранит только пользовательские предпочтения UI;
- `I18n` определяет активную локаль и предоставляет реактивные переводы по
  исходным ключам;
- `OperationCenter` сводит длительные действия и их результаты в одно место;
- `OperationBridge` переводит состояния доменных контроллеров в операции;
- `SystemTelemetryController` и `SystemSnapshotsController` отделены от
  большого системного контроллера и запускаются только по запросу страницы.

Поиск передаёт странице стабильный `target`; страница реализует
`revealSection(target)` и сама знает геометрию своих секций. Поэтому новый
поисковый маршрут не должен добавлять координаты в composition root.

## Добавление настройки

1. Определить владельца значения: конфиг, контроллер или внешний сервис.
2. Использовать существующий `Miko*Row`.
3. Сохранение, команды и ошибки разместить в контроллере.
4. Необязательные действия закрыть capability-проверкой.
5. Для рискованных изменений добавить подтверждение и откат.
6. Обернуть пользовательский текст в `I18n.tr` и обновить языковые каталоги.

## Добавление секции

1. Создать небольшой QML-компонент.
2. Явно передать `style` и данные.
3. Изменения сообщать сигналами.
4. Подключить секцию к нужной странице.
5. Повторяющиеся паттерны вынести в общий примитив.

## Добавление вкладки

1. При необходимости создать `ExampleController.qml`.
2. Создать `ExamplePage.qml` и секции.
3. Добавить метаданные в `PageRegistry.pages`.
4. Добавить полезные поисковые пункты.
5. Подключить контроллер и страницу в `control-center.qml`.
6. Расширять `Router.qml` только при наличии вложенной навигации.
7. Проверить поиск, «Назад», минимальный размер и unavailable-состояния.

Проводка намеренно явная. Загрузка сторонних модулей по манифестам пока не
реализована.

# Miko OS Control Center

Этот каталог содержит интерфейс и прикладную логику центра управления. Главный
`control-center.qml` остаётся точкой сборки приложения: он создаёт сервисы,
контроллеры и страницы, но не должен содержать разметку отдельных разделов.

## Переносимость и состав поставки

Сейчас центр управления является модулем оболочки `ii`, а не автономным QML-
пакетом. Копирования одного каталога `controlcenter/` недостаточно. Для запуска
нужны:

- `control-center.qml` и весь каталог `controlcenter/`;
- импорты `qs.services`, `qs.modules.common`,
  `qs.modules.common.functions` и `qs.modules.common.widgets`;
- используемые ими singleton-модели `Appearance`, `Config`, `Audio`, `Network`,
  `KdeConnect`, `Updates`, `HyprlandData` и остальные сервисы точки сборки;
- Quickshell с Qt Quick Controls, PipeWire и Bluetooth-модулями.

Пути к домашнему каталогу, state-файлам и Miko-скриптам вычисляет
`Environment.qml`; имя пользователя в них не зашито. При этом текущий полный
профиль рассчитан на Arch-подобную систему с Hyprland: управление пакетами
использует pacman/paru, а часть экранных и сетевых функций — Hyprland и
Miko Resilience. KDE Connect, Throne, EasyEffects, DDC/CI и SMART являются
дополнительными интеграциями.

`Capabilities.qml` уже собирает наличие команд, но ещё не все действия
контроллеров используют этот каталог для блокировки неподдерживаемых кнопок.
Поэтому на другой системе интерфейс может открыться, однако до появления полной
capability-маршрутизации безопасно считать поддерживаемой конфигурацией именно
полный `ii`-runtime на Arch/Hyprland. Отсутствующая интеграция должна постепенно
превращаться в понятное disabled-состояние, а не в новую проверку, размазанную
по страницам.

Рекомендуемая структура установки:

```text
${XDG_CONFIG_HOME:-$HOME/.config}/quickshell/ii/
├── control-center.qml
├── controlcenter/
├── modules/
└── services/
```

Лаунчер и `.desktop`-файл не являются частью QML-модуля. Экспортёр ниже включает
их при наличии, делает launcher XDG-aware и заменяет абсолютный пользовательский
`Exec=/home/...` на переносимый `Exec=miko-control-center`.

### Безопасный экспорт

`tools/build-bundle.sh` создаёт архив, но ничего не устанавливает и не меняет в
live-конфиге. Существующий архив он намеренно не перезаписывает.

Минимальный source bundle:

```bash
"$QS_ROOT/controlcenter/tools/build-bundle.sh" \
  /tmp/miko-control-center-source.tar.gz
```

Для переноса на другую машину можно явно включить весь runtime `ii`:

```bash
"$QS_ROOT/controlcenter/tools/build-bundle.sh" --full-runtime \
  /tmp/miko-control-center-full.tar.gz
```

Внутри используются каталоги `xdg-config/`, `xdg-data/` и `bin/`, лежат
`manifest.env`, `files.sha256` и инструкция `BUNDLE.md`. Full-runtime следует
просмотреть перед публикацией: вместе с рабочими импортами он может содержать
локальные пользовательские настройки. Сам архив получает права `0600`.

## Слои

### 1. Primitives

Общие визуальные элементы начинаются с `Miko`:

- `MikoStyle.qml` — единые цвета, радиусы, интервалы и длительности;
- `MikoPageFlickable.qml` — прокрутка страницы и клавиши Home/End/Page Up/Down;
- `MikoSurface.qml` — поверхность или карточка;
- `MikoButton.qml`, `MikoIconDisc.qml` — кнопка и иконка;
- `MikoListGroup.qml`, `MikoListRow.qml` — сгруппированные строки;
- `MikoToggleRow.qml`, `MikoStepperRow.qml` — стандартные настройки.

`MikoStyle` использует короткий desktop-motion без scale-анимации текста:
120 мс для hover/press, 180 мс для обычного изменения и 220–260 мс для входа
или раскрытия. Hover-состояние обязано оставаться плотной поверхностью, а не
наследовать глобальную прозрачность оболочки. Тяжёлые blur/shadow-эффекты в
строках и карточках не добавляются: глубину создают тон, hairline и композиция.

Примитив не знает о странице, системной службе или глобальном `root`. Он получает
`required property var style` и данные, рисует одно состояние и сообщает о
действии сигналом.

Если один и тот же паттерн встречается минимум в двух разделах, его следует
сделать примитивом или небольшим секционным компонентом, а не копировать.

### 2. Controllers

Контроллеры заканчиваются на `Controller.qml`:

- `AppearanceController.qml`;
- `ApplicationsController.qml`;
- `AudioController.qml`;
- `DevicesController.qml`;
- `DisplayController.qml`;
- `NetworkController.qml`;
- `ServicesController.qml`;
- `SystemController.qml`.

Контроллер хранит состояние предметной области, выполняет чтение и команды,
разбирает вывод процессов и предоставляет UI понятные свойства и функции.
Контроллер не должен содержать карточки, размеры или другую разметку.

Для потенциально опасной операции предпочтителен двухэтапный контракт:

1. контроллер формирует описание и состояние подтверждения;
2. страница показывает подтверждение и только после него вызывает выполнение.

Обновления, удаление пакетов, очистка, изменение дисплеев и перезапуск служб
никогда не должны запускаться из `Component.onCompleted`.

### 3. Pages and sections

Файл `*Page.qml` собирает страницу из секций. Например:

- `OverviewPage.qml` использует `OverviewHero`, `OverviewMetrics`,
  `OverviewQuickActions` и `OverviewStatusCards`;
- `NetworkPage.qml` переключает `NetworkOverview`, `NetworkThrone` и
  `NetworkPorts`;
- `DisplayPage.qml` собирает топологию, режимы, сцены и комфорт;
- `SoundPage.qml`, `DevicesPage.qml`, `AppearancePage.qml`,
  `ApplicationsPage.qml`, `SystemPage.qml` и `ServicesPage.qml` отвечают каждый
  только за свой раздел.

Страница:

- получает данные через `required property`;
- получает `style`;
- сообщает о намерениях сигналами (`stopRequested`, `navigateRequested` и т.п.);
- не ищет родительское окно через неявную область видимости;
- не дублирует процессы контроллера.

Страницы не получают главное окно как `host`. Обзор получает четыре предметных
контроллера, а системная и сервисная страницы — по одному контроллеру и явный
сигнал навигации. Благодаря этому разметку можно запускать с тестовыми моделями,
не поднимая настоящие команды pacman, systemctl или UFW.

### 4. Registry and environment

- `PageRegistry.qml` — единственный каталог страниц и поисковых пунктов;
- `Router.qml` — текущая страница, вложенный раздел и логика «Назад»;
- `Environment.qml` — вычисленные пути без захардкоженного имени пользователя;
- `Capabilities.qml` — редкая проверка доступных команд и интеграций.

`PageRegistry.pages` является единственным каталогом `pageId`. `Router` хранит
`currentPageId`, а числовой `currentPage` вычисляется только для совместимости
со старым IPC `open(int)`. Поиск, сигналы страниц и новые IPC-маршруты должны
передавать строковый `pageId`, поэтому перестановка элементов реестра больше не
ломает внутреннюю навигацию.

## Контракт `required property`

Обязательное свойство означает реальную зависимость компонента. Его нужно
передавать в точке сборки явно:

```qml
ControlCenter.SoundPage {
    audio: Audio
    controller: audioController
    effects: EasyEffects
    style: ui
}
```

Правила:

- `style` передаётся всем визуальным компонентам;
- singleton или модель передаются под предметным именем (`audio`, `network`);
- процесс передаётся только временно, пока его не поглотил контроллер;
- callback применяется для маленького синхронного действия;
- сигнал применяется, когда действие меняет систему или принадлежит родителю;
- компонент не должен молча использовать лексический `id` из другого файла.

Если зависимость необязательна, у неё должен быть безопасный default и UI обязан
показывать недоступное состояние, а не кнопку, которая завершится ошибкой.

## Как добавить страницу

1. Создать `ExamplePage.qml` на основе `MikoPageFlickable`.
2. Разбить крупные независимые блоки на `Example*.qml`.
3. Передать `style`, модели и контроллеры через `required property`.
4. Описать действия сигналами; подключить их в точке сборки.
5. Добавить запись в `PageRegistry.pages`.
6. Добавить только полезные поисковые входы в `PageRegistry.searchable`.
7. Добавить состояние вложенной навигации в `Router.qml`, если оно действительно
   необходимо, и учесть его в `canGoBack` и `back()`.
8. Подключить страницу под тем же `pageId` в `pageComponents` главного файла.
9. Проверить, что поиск и `navigateRequested` используют этот `pageId`, а не
   позицию страницы в массиве.

Страница не добавляет собственную копию заголовка окна, поиска или кнопки
закрытия — это chrome главного приложения.

## Как добавить настройку

1. Определить владельца состояния: Config, singleton, controller или внешний
   сервис.
2. Для обычного boolean использовать `MikoToggleRow`.
3. Для дискретного числа использовать `MikoStepperRow`.
4. Для перехода или команды использовать `MikoListRow` и сигнал.
5. Сохранение и разбор ошибок разместить в контроллере.
6. Для недоступной capability показать disabled-состояние и короткую причину.
7. Если изменение рискованное, добавить preview/confirm/rollback, как у экранов.

Нельзя создавать новый визуальный вариант строки только из-за одной страницы:
сначала расширяется существующий primitive совместимым свойством.

## Безопасная проверка

Сначала проверяется только синтаксис и зависимости:

```bash
QS_ROOT="${XDG_CONFIG_HOME:-$HOME/.config}/quickshell/ii"
qmllint -I "$QS_ROOT" "$QS_ROOT/controlcenter/ExamplePage.qml"
```

На полной Miko OS после этого проверяется вся оболочка:

```bash
if command -v miko-check >/dev/null 2>&1; then
  miko-check desktop
fi
```

`qmllint` является статической первой проверкой, но не заменяет runtime-проверку
Quickshell singleton-моделей. Новый экземпляр нужно запускать отдельно от
основной оболочки:

```bash
qs -p "$QS_ROOT/control-center.qml"
```

После запуска навигацию можно проверять без кликов через IPC:

```bash
qs -p "$QS_ROOT/control-center.qml" ipc call controlCenter route network
qs -p "$QS_ROOT/control-center.qml" ipc call controlCenter network ports
qs -p "$QS_ROOT/control-center.qml" ipc call controlCenter appearance wallpaper
qs -p "$QS_ROOT/control-center.qml" ipc call controlCenter inspect quickshell
```

Клавиатурный контракт приложения:

- `Ctrl+F` или `Ctrl+K` — поиск;
- `Enter` в поиске — открыть первый результат;
- `Alt+←` — вернуться из вложенного раздела;
- `Esc` — сначала выйти из поиска, затем из вложенного раздела, затем закрыть;
- `Home`, `End`, `Page Up`, `Page Down` — быстрая прокрутка страницы.

На Hyprland Qt-ограничения минимального размера не действуют на tiled-окно.
Поэтому live-профиль Miko OS использует узкое правило только по title
`^Miko Control Center$`: float, center и размер 1180×760. Это интеграция
композитора, а не обязательная часть QML; на другой машине её можно заменить
правилом своего оконного менеджера.

Допустимы только навигация, прокрутка, раскрытие карточек и read-only refresh.
Основной экземпляр Quickshell ради такой проверки не перезапускается.

Во время визуальной или архитектурной проверки нельзя нажимать и автоматически
вызывать:

- обновление системы или AUR;
- установку и удаление пакетов;
- очистку кэша, корзины, журнала или orphan-пакетов;
- restart/stop/start системных и пользовательских служб;
- применение схемы мониторов без preview и отката;
- открытие/закрытие firewall-портов.

Для теста опасной карточки передаётся mock action с `running: false` и методом,
который только записывает намерение. Автоматические процессы страницы должны
быть read-only и останавливаться при уничтожении страницы.

## Одноразовый migration tool

`tools/prune-legacy-components.mjs` нужен только для удаления десяти известных
legacy-компонентов из старого монолитного `control-center.qml`. Для runtime,
установки на чистую машину и дальнейшего добавления страниц он не нужен.

Скрипт использует только встроенные модули Node.js. Без `--apply` он выполняет
dry-run и сообщает предполагаемый размер результата:

```bash
node "$QS_ROOT/controlcenter/tools/prune-legacy-components.mjs" \
  "$QS_ROOT/control-center.qml"
```

`--apply` переписывает переданный файл на месте и сам не создаёт backup. Его
можно использовать только на ожидаемой старой ревизии, где присутствуют все
перечисленные legacy-id, предварительно сохранив копию и просмотрев dry-run.
Повторно запускать его на уже декомпозированном центре или на чужом форке не
следует: отсутствие хотя бы одного ожидаемого блока намеренно завершает скрипт
ошибкой до записи.

## Definition of done

Изменение готово, когда:

- `qmllint` не сообщает ошибок в изменённых файлах;
- на полной Miko OS проходит `miko-check desktop`;
- страница открывается, прокручивается и возвращается назад;
- минимальный размер окна не обрезает обязательные элементы;
- unavailable-состояния понятны;
- нет дублирующей старой разметки, создающей delegates в фоне;
- ни одно системное изменение не выполняется до явного действия пользователя;
- новая логика находится в контроллере или секции, а не раздувает main QML.
